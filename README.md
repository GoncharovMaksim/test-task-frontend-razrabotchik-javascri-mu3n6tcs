## 1. Обзор проекта

Полнофункциональное Single Page Application (SPA) на стеке **React + Redux Toolkit + TypeScript (Strict Mode)**, разработанное в рамках тестового задания на позицию **Frontend разработчик (JavaScript/TypeScript + React) Middle** в **ГК Калуга Астрал**.

### Реализованный уровень: «Полный»
- Главная страница (`/`) с обзором возможностей, архитектурным чек-листом и навигацией.
- Страница авторизации (`/login`) с центрированной формой, валидацией `admin/admin` и выводом ошибки при неверных данных.
- Страница карточек для изучения иностранных слов (`/cards`), закрытая за авторизацией (Protected Route).
- Страница редактирования профиля (`/profile`), закрытая за авторизацией (Protected Route).
- Интерактивный раздел с ответами на теоретические вопросы ТЗ (`/theory`).

## 2. Архитектура и компонентная иерархия

Архитектура строго следует предписанной в ТЗ иерархии компонентов:

```text
Page (непосредственно страница целиком, объединяет Header, Body, Footer)
 ├── Header (принимает данные профиля через props; навигация, статус сессии, выход)
 ├── Body (содержит полезную нагрузку: карточки или форму профиля)
 │    ├── CardList (принимает массив карточек через props; фильтры, поиск)
 │    │    └── Card (рендерит карточку, принимает все данные через props, CSS 3D Flip)
 │    └── EditView (форма редактирования профиля, принимает массив полей через props)
 │         └── Field (рендерит один из 7 типов полей, состояния disabled/hidden)
 └── Footer (принимает контакты HR и офиса через props)
```

### Принцип проброса данных (Props Drilling Contract):
- В компоненте `Page` данные для `Header` (профиль, логин, аватар) и `Footer` (компания, контакты, адрес, телефон) передаются строго через интерфейсы пропсов `HeaderProfileProps` и `FooterContactsProps`.
- Компонент `CardList` принимает массив объектов карточек `CardItem[]` и передает конкретный объект в компонент `Card`.
- Компонент `EditView` принимает массив определений полей `FieldDefinition[]` и значения `ProfileData`, делегируя рендеринг каждому компоненту `Field`.

## 3. Карточки для изучения слов (`/cards`)

- **Мотивационный заголовок:** Случайно/предустановленно выбирается из пула цитат (*"Word of the Day"*, *"Daily Vocabulary Boost"*, *"Language Insight of Today"*).
- **Английское слово:** Название, транскрипция, часть речи, аудио-озвучка произношения (Web Speech API).
- **Пример использования:** Контекстное предложение в кодовой/инженерной тематике.
- **Кнопка действия (`LEARN MORE`):**
  - При клике срабатывает плавная **CSS 3D анимация переворота** (свойства `perspective: 1000px`, `transform-style: preserve-3d`, `rotateY(180deg)`).
  - На обратной стороне отображаются русский перевод и подробное толкование на английском языке.
  - Повторный клик по кнопке `НА ЛИЦЕВУЮ` возвращает карточку в исходное состояние.
- **Дополнительный функционал:**
  - Полнотекстовый поиск по слову, переводу и примеру.
  - Фильтрация по категориям.
  - Счетчик изученных слов с возможностью отметить слово как освоенное.
  - Быстрые действия: «Перевернуть все» и «Сброс».

## 5. Ответы на теоретические вопросы (JS / TypeScript)

Полный интерактивный блок ответов доступен на странице `/theory`. Ниже приведены ключевые тезисы:

### 1. «Строгий режим» ("use strict")
Директива ES5. Предотвращает случайное создание глобальных переменных (выбрасывает `ReferenceError`), запрещает опасные конструкции (`with`, удаление неперечисляемых свойств), делает `this === undefined` в функциях без контекста, а также помогает JIT-компиляторам V8 оптимизировать исполнение кода. В ES6-модулях строгий режим включен автоматически.

### 2. Отличие var, let, const
- `var`: функциональная область видимости, всплытие (hoisting) с инициализацией `undefined`, разрешено повторное объявление.
- `let`: блочная область видимости `{ }`, временная мертвая зона (TDZ) до инициализации, повторное объявление запрещено, значение переприсваиваемо.
- `const`: блочная область видимости, TDZ, запрет повторного присвоения ссылки.
- **Рекомендация:** По умолчанию использовать `const`. Если переменная реально мутирует (счетчики) — `let`. От `var` отказаться полностью.

### 3. Операторы сравнения
- `==` приводит операнды к общему типу (Coercion), `===` проверяет равенство типов и значений без приведения.
- `'01' == 1`: **`true`** (строка `'01'` приводится к числу `1`).
- `'01' === 1`: **`false`** (разные типы `string` и `number`).
- `null === undefined`: **`false`** (разные типы).
- `null == undefined`: **`true`** (специальное правило спецификации ECMA-262: равны друг другу и ничему более).
- `null > 0`: **`false`** (`Number(null)` равен 0; `0 > 0` ложно).
- `null == 0`: **`false`** (`null` не приводится к числу оператором `==`).
- `null >= 0`: **`true`** (оператор `>=` использует алгоритм `ToNumber`, где `0 >= 0` истинно).
- `undefined > 0`, `undefined < 0`, `undefined == 0`: все **`false`** (`Number(undefined)` равен `NaN`, а любое математическое сравнение с `NaN` возвращает `false`).

### 4. Сохранение функции в переменную
Да. В JavaScript функции — это «объекты первого класса» (First-Class Citizens). Их можно сохранять в переменные (Function Expression), передавать как аргументы и возвращать из функций.

### 5. Функция подтверждения действия с колбэками и prompt
```typescript
function confirmAction(
  question: string,
  onConfirm: () => void,
  onCancel: () => void
): void {
  const answer = window.prompt(`${question}\n(Введите "да" или "yes" для подтверждения):`);
  if (answer !== null && ['да', 'yes', 'y', '1'].includes(answer.trim().toLowerCase())) {
    onConfirm();
  } else {
    onCancel();
  }
}
```

### 6. Объекты, методы, this
`this` — ссылка на текущий контекст выполнения. Потеря контекста происходит при передаче метода объекта как изолированной функции-колбэка (например, в `setTimeout(obj.greet, 100)`).  
Решения:
- Привязка через `.bind(this)` (создает связанную функцию).
- Использование стрелочных функций `() => obj.greet()` (стрелочные функции берут `this` лексически из окружающего контекста).

### 7. setTimeout и setInterval
- `setTimeout` планирует однократный вызов, `setInterval` — периодический цикл.
- **Отличие от рекурсивного `setTimeout`:** в `setInterval` интервал отсчитывается между стартами выполнения; если тело функции выполняется дольше интервала, вызовы начинают накладываться без пауз. Рекурсивный `setTimeout` планирует следующий такт только **после завершения** предыдущего, гарантируя точную паузу.
- Отмена: `clearTimeout(id)` и `clearInterval(id)`.

### 8. TypeScript: особенности и дженерики
- **Зачем нужен:** Добавляет статическую строгую типизацию поверх JavaScript для исключения ошибок на этапе компиляции, автодополнения и безопасного рефакторинга.
- **Базовые типы:** `boolean`, `number`, `string`, `null`, `undefined`, `symbol`, `bigint`, `any`, `unknown`, `never`, `void`, кортежи `[T, U]`, массивы `T[]`.
- **Дженерики (Generics):** Параметризованные типы, позволяющие писать универсальный переиспользуемый код (например, `interface ApiResponse<T> { data: T; status: number }`).
- **type vs interface:** Интерфейсы поддерживают слияние объявлений (Declaration Merging) и расширение через `extends`; типы поддерживают примитивы, Union (`A | B`), Intersection (`&`) и кортежи.
- **Необязательные свойства:** Символ `?` в определении свойства (`age?: number`), либо утилита `Partial<T>`, делающая все поля объекта необязательными.
- **Omit<T, K>:** Создает новый тип, исключая из `T` указанные свойства `K` (`Omit<User, 'id'>`).
- **Перегрузка функций:** Поддерживается объявлением нескольких заголовков функций перед одной реализацией.

## 6. Локальный запуск и тестирование

### Требования
- Node.js >= 18.0.0
- npm >= 9.0.0

### Команды
```bash
# Установка зависимостей
npm install

# Запуск в режиме разработки (Vite HMR)
npm run dev

# Запуск модульных и интеграционных тестов (Vitest)
npm test

# Сборка production-бандла
npm run build
```
